# Component authoring guide

`shadcn-zui` is a component library for [zui](../../zui) styled after
shadcn/ui, laid out like [gpui-kit](https://github.com/longbridge/gpui-kit).
gpui-kit is cloned into `.references/gpui-kit` (gitignored) as a reference.

## Layout

```
src/
  root.zig                  -- public surface (re-exports)
  theme/mod.zig             -- design tokens (dark palette)
  support/mod.zig           -- label/strong/icon text helpers
  components/
    root.zig                -- component namespace
    <name>/mod.zig          -- one folder per component
    icon/
      mod.zig               -- Name enum, bytes(), Icon builder
      icons_generated.zig   -- GENERATED by tools/gen_icons.py (do not edit)
      assets/icons/*.svg    -- 1830 Lucide icons (copied from gpui-kit)
      assets/default-icons.txt
examples/gallery/main.zig    -- visual gallery
tools/gen_icons.py           -- regenerates icons_generated.zig
```

## Conventions

- One folder per component: `src/components/<name>/mod.zig`. Export a builder
  struct with chainable methods that return `Self` by value and a
  `render() zui.Element`.
- The struct is the configuration; `render` composes the element. Never store
  a `zui.Element` inside the builder — elements are frame-local indices and
  only valid during the render pass that created them.
- Names follow gpui-kit: `Button`, `IconButton`, `Badge`, `Avatar`,
  `Checkbox`, `Switch`, `Tabs`, `Table`, `Input`, `Separator`, `Spinner`,
  `AreaChart`, `Card`.
- Colors/metrics come from `../../theme/mod.zig`, never hardcoded hex, except
  inside SVG generators (they emit hex strings for nanosvg).
- Interaction listeners are built by the app (`cx.listener(...)`) and passed
  in as `?zui.Listener`; the library never depends on the app's state type.
- Text: use `support.label(text, size, color)` / `support.strong(...)`, or
  `zui.text(value, .{ .font = theme.font, .size = ..., .line_height = ..., .weight = ..., .color = ... })`.
- Icons: `@import("../icon/mod.zig")`, then `.render(name, size, color)` or
  `Icon.init(name).size(n).color(c).render()`. Enum names are snake_case
  versions of the Lucide file names (`.chevron_down`, `.circle_check`,
  `.loader`, `.search`, `.plus`, `.x`, ...). `Name` is generated from the
  full catalog, so prefer common Lucide names that exist.
- Buttons: compose `Button`/`IconButton` from `../button/mod.zig` instead of
  re-implementing pill styles.

### Zig gotchas (each of these broke a build before)

- **Field/method name collisions**: a struct can't have a field `color` and a
  method `color()`. Suffix the field (`color_value`) or the method.
- **Shadowing**: captures and locals must not shadow a method or field name
  reachable in scope (`|width|` when a `width()` method exists, `const image`
  next to an `image()` method). Pick different local names.
- `switch` is a keyword: name the folder/import with `@"switch"` or a synonym.
- Every function parameter must be used or explicitly discarded
  (`_ = param;`) — and discarding a parameter you *do* use is an error.
- `@intFromEnum` is `@backingInt` in this Zig (0.17-dev); `zig fmt` migrates it.
- Keep float math in `f32` (builder APIs are `f32`); watch for accidental
  `f64` from `@floatFromInt` promotions.
- Text/image slices are **borrowed until paint**: never return text backed by
  a function-local buffer or a by-value copy — borrow from caller-owned data
  (see `Avatar.render`).
- Run `zig fmt` on your files before finishing (`zig fmt src/components/<name>/mod.zig`).

### Unit tests

`zig build test` compiles every component and runs its tests. **Never build
zui elements in a unit test**: `zui.div()`/`zui.text()`/`.render()` panic
outside a render frame ("ZUI elements must be built during render"). Test
pure logic instead (metrics, color resolution, layout math, SVG generation
with an allocator). Element behavior is verified visually via the gallery
snapshot (`zig build snapshot-gallery`).

## zui API cheat sheet

```zig
const zui = @import("zui");

zui.div()                       // container element
zui.text("hi", .{ .font = theme.font, .size = 14, .line_height = 20, .weight = .semibold, .color = c })
zui.svg(bytes)                  // SVG element; .tint(color) recolors currentColor
zui.img(bytes)                  // raster image
zui.spacer()                    // flex_1 spacer
zui.when(cond, if_true, if_false)
```

Element methods: `flex_row flex_col flex_1 items_center justify_center
justify_between gap w h w_full h_full size size_full max_w_full p px py pl pr
pt pb pb pl absolute inset top right left bg bg_gradient opacity blur
rounded_lg (8) rounded_xl (12) rounded_2xl (16) rounded_full (999) rounded(px)
border_1 border_2 border_b_1 border_dashed border_color shadow_lg text_color
cursor_pointer cursor_text object_fit grayscale tint hover_bg hover_border
on_click on_mouse_down on_mouse_up on_mouse_move on_scroll
on_double_click flex_wrap scroll_x scroll_y withFocus child`.

Not available: `justify_end`, align end, `min_w`, underline, transitions.
Work around them with spacers/absolute positioning. `Element.rounded(px)`
(added to zui for this library) sets an arbitrary corner radius. `h_full`
and `pb` were also added for this library (sidebar full height; dropdown
separator spacing).

Since the first component drop, zui also re-exports `zui.Listener` from its
root; components use `?zui.Listener` for interaction callbacks.

### Namespace notes

- Module-level types are re-exported at the crate root for ergonomics:
  `shadcn.TabItem`, `shadcn.TableColumn`, `shadcn.TableRow`,
  `shadcn.ChartSeries`, `shadcn.CardMetric`.
- `Card.metric(Metric)` is a static constructor returning an element;
  `Card.init()` returns the generic `Card.Builder`.
- `Spinner.render()` takes `*Spinner` (it rebuilds its rotated SVG into an
  internal buffer each frame); everything else renders by value.
- `Avatar.render()` borrows initials letters from the caller-owned `name`
  (or an explicit `.letters()` override) because zui text keeps slices
  borrowed until paint.

Colors (from `theme`): `background foreground page card card_metric
card_foreground popover popover_foreground primary primary_foreground
primary_hover secondary secondary_foreground secondary_hover muted
muted_foreground accent accent_foreground accent_hover destructive
destructive_foreground destructive_hover success warning border
border_strong input_border ring sidebar sidebar_foreground sidebar_accent
sidebar_border chart_1 chart_2 chart_3 body faint white`. Also
`theme.font`, `theme.radius*`.

## Build commands

```sh
zig build test               # compile library + unit tests
zig build run-gallery        # open the gallery window
zig build snapshot-gallery   # headless render to /tmp/opencode/shadcn-gallery.ppm
zig build selftest-gallery   # headless click-through self-test (31 checks)
python3 tools/gen_icons.py   # regenerate icon enum/table (only when assets change)
```

Snapshot/review extras (all optional env vars on the gallery binary):
`ZUI_SNAPSHOT_WIDTH`/`ZUI_SNAPSHOT_HEIGHT` (also `-Dsnapshot-width/-height`),
`ZUI_SNAPSHOT_PAGE=<name>` for a per-page snapshot
(buttons|inputs|feedback|overlays|data|charts|navigation), and
`ZUI_SNAPSHOT_OPEN=dialog|alert|sheet|popover|menu|tooltip|toast` to pre-open
an overlay for reviewing its open state and measuring click coordinates.
The selftest logs each click's matched hit region with `ZUI_SELFTEST_DEBUG=1`.
